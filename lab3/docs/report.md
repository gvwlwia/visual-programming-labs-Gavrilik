### Часть 2. Build Guides (до / после)

**Что изучено.** В разделе Build Guides Bubble сформировал персональные Build Docs для моего приложения «Список путешествий»: публичный доступ, структура страницы header + body + footer, добавление, редактирование, удаление и список путешествий. Подробно я изучила два гайда: «Список путешествий» и «Добавление путешествий».

![Гайд «Список путешествий»](../screenshots/02-buildguide-1.png)

![Гайд «Добавление путешествий»](../screenshots/02-buildguide-2.png)

**Что показалось полезным.**
- Из гайда «Список путешествий»: как данные выводятся в виде списка и как их можно отфильтровать и посчитать. Я сопоставила шаги гайда с тем, что сгенерировал AI-агент, и увидела, какие элементы отвечают за вывод данных.
- Из гайда «Добавление путешествий»: какие поля нужны форме и как они связаны с данными.

**Что взято в приложение.** В приложении, сгенерированном агентом, в верхнем блоке был только общий счётчик поездок. По идее из гайда о работе со списком данных я добавила счётчики по статусам: «Завершено» и «Запланировано». Каждый счётчик считает записи типа «Поездка» с ограничением по статусу.

**Как это сделано.** В редакторе (вкладка Design) я скопировала плашку с общим счётчиком (Total Text) и изменила выражение в поле Text: в окне Search for Поездка во вкладке Constraints добавила ограничение «Статус = Завершено» и оставила функцию :count. Перед выражением вписала подпись «Завершено: ». Так же сделала счётчик для статуса «Запланировано».

**Что сгенерировал AI, а что сделано вручную.** Общий счётчик, карточки и цветное оформление статуса (три условия во вкладке Conditional у Badge Text) создал AI-агент. Счётчики по статусам я добавила сама.

### Часть 3. Ручная доработка UI

Всё в этой части сделано вручную, без AI-агента.

#### 3.1. Заголовок с именем

Заголовок находится внутри многоразового элемента Header, поэтому для правки я открыла сам Header (через выпадающий список страниц вверху редактора) и в поле Content → Text дописала своё имя. Фамилия уже есть в футере из промпта («ТВП: Гаврилик»). Получился текст: **«Список путешествий · Александра»**. Так как Header многоразовый, имя отображается на всех страницах, где он используется.

![Заголовок с именем](../screenshots/03a-header-title.png)

#### 3.2. Global variable для цвета

Я создала цветовую переменную **`primary-color`** со значением **`#2196f3`** (основной синий цвет приложения, как у кнопки «Добавить поездку»). Создание выполнено в палитре цвета, в блоке Variables (кнопка «+»). Затем я применила переменную к элементу страницы, выбрав её из списка Variables, а не из палитры (результат виден на скриншоте 03b).

Смысл переменной: если изменить её значение, цвет обновится сразу у всех элементов, к которым она применена, и не нужно править каждый вручную.

![Список переменных с primary-color](../screenshots/03-global-variable.png)

![Переменная применена к элементу](../screenshots/03b-variable-applied.png)

#### 3.3. Новый стиль

Я создала стиль **`travel-primary-button`** (Element style: Button) на основе кнопки «Добавить поездку» (Add Button). В настройках стиля фон (Background) задан переменной `primary-color`, цвет текста белый. Стиль применён к кнопке «Добавить поездку»: его название отображается в её Properties.

![Стиль travel-primary-button](../screenshots/04-style.png)

#### 3.4. Готовый компонент

Из каталога Install More я установила бесплатный плагин **Testimonial Section Slider** и добавила его на страницу index, так как такого элемента на ней ещё не было. Отзывы задаются в поле JSON Data списком объектов с полями имени, подписи и текста. Заглушку (Sarah Anderson, Lorem ipsum) я заменила своими отзывами о путешествиях. В Preview слайдер прокручивается, отзывы отображаются (см. скриншот).
